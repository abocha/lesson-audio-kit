# Lesson Audio Kit - Testing Strategy

This document outlines the testing strategy for the Lesson Audio Kit project, covering unit, integration, and end-to-end (E2E) tests.

## Guiding Principles

* **Test Pyramid**: Focus on a strong base of unit tests, complemented by integration tests for service interactions, and a smaller set of E2E tests for critical user flows.
* **Automation**: All tests should be runnable automatically and integrated into the CI pipeline.
* **Clarity and Maintainability**: Tests should be clear, easy to understand, and maintainable.
* **Coverage**: Aim for high logical coverage for critical components, especially in the `dialogue_tts_core` library.
* **Idempotency**: Tests should be runnable multiple times with consistent results (mocking external services where necessary).

## Tools and Frameworks

* **Test Runner**: Pytest
* **Mocking**: `pytest-mock` (unittest.mock)
* **API Testing**: `httpx` (for client-side testing of FastAPI endpoints)
* **E2E Testing (UI)**: Playwright (for Gradio and Streamlit UIs - *planned, lower priority for MVP*)
* **HTTP Interaction Recording (for external APIs)**: `pytest-vcr` (*planned for TTS/LLM client tests*)
* **Linting & Formatting**: Ruff (already in use)
* **CI**: GitHub Actions (already in use)

## Test Execution in CI

* **Unit & Integration Tests**: `pytest tests/` will be run on every push/PR to main/develop branches.
  * Markers can be used (e.g., `@pytest.mark.integration`, `@pytest.mark.api`) to run subsets if needed.
* **E2E Tests**: (Planned) Will run nightly or on release branches, requiring secrets for actual external API calls (if not fully mocked).
* **VCR Cassettes**: (Planned) Cassettes for external API interactions will be committed to the repository. A mechanism to re-record cassettes will be needed (e.g., specific pytest flag or environment variable).

## Coverage Goals

* `dialogue_tts_core`: Aim for >90% line/branch coverage.
* API Endpoints: Aim for >80% coverage of endpoint logic (excluding auto-generated FastAPI validation).
* UI Event Handlers/Logic: Aim for >70% coverage for critical paths.
